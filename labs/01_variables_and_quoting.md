# Лаба 1: Переменные и кавычки

Большинство ошибок в bash-скриптах — из-за неправильных кавычек и необъявленных переменных.

## Теория в двух строках
- `"$var"` — значение подставляется, пробелы сохраняются как есть; `'$var'` — буквальная строка без подстановки.
- Всегда пишите `"$var"` в кавычках, если не нужно разбиение по пробелам.

## Задания

1. Создайте файл `my file.txt` (с пробелом в имени). Напишите команду, которая выводит его размер через переменную:
   ```bash
   f="my file.txt"
   wc -c $f        # что произойдёт?
   wc -c "$f"      # а так?
   ```
2. Выведите значение переменной `HOME`, и литерал `$HOME` — одной командой `echo`.
3. Задайте значение по умолчанию: если переменная `NAME` не задана, использовать `guest`.
4. Требуйте обязательный аргумент: если `$1` пуст — завершить скрипт с сообщением об использовании.
5. Получите имя файла без расширения и расширение из `report.final.tar.gz`.

## Решения

```bash
# 1. Без кавычек bash разобьёт имя на два слова: wc ищет файлы "my" и "file.txt"
wc -c "$f"

# 2.
echo "$HOME и литерал "'$HOME'

# 3.
name="${NAME:-guest}"

# 4. (так сделано в scripts/backup.sh)
src="${1:?usage: script.sh <src>}"

# 5. Расширение параметров
file="report.final.tar.gz"
echo "${file%%.*}"    # report        — удалить самый длинный суффикс от первой точки
echo "${file%.*}"     # report.final.tar
echo "${file#*.}"     # final.tar.gz  — удалить кратчайший префикс до точки
echo "${file##*.}"    # gz
```

## Режим «строгого» скрипта
Начинайте скрипты с:
```bash
set -euo pipefail
```
- `-e` — выход при ошибке команды;
- `-u` — ошибка при обращении к необъявленной переменной;
- `-o pipefail` — код возврата конвейера = код первой упавшей команды.

Когда команда может штатно вернуть ненулевой код, обработайте это явно: `grep -q foo file || true`.
